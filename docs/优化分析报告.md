# AI 短视频电商提效系统 - 优化分析报告

## 一、本次任务

把实操测试项目升级为可上传 GitHub、可现场演示、可讲清楚架构的完整工程：
先对照开源项目找差距，再动手改进。本报告记录分析结论、借鉴来源与改进明细。

## 二、重构前的产品现状

重构前是三个可运行的 Python 脚本：

| 模块 | 职责 | 实现方式 |
| --- | --- | --- |
| ai_workflow.py | 商品 -> 卖点 -> 内容角度 -> 脚本 -> 质检 | 命令行交互，每步人工确认 |
| script_agent.py | 输入商品名生成脚本 | 命令行交互 |
| data_analysis.py | 读取投流数据做复盘 | 命令行 + AI 报告 |

配套：8 张 CSV 业务表、SQLite 初始化脚本、知识库 prompts.json、基础测试。

## 三、优点（可以保留并写进简历）

1. **业务理解完整**：覆盖选品、内容、脚本、视频、投流、客服、复盘、知识库
   八大板块，流程设计有真实业务依据。
2. **AI 工作流逻辑清晰**：四步生成链路（卖点 -> 角度 -> 脚本 -> 质检），
   有重试与人工审核节点，符合真实内容生产流程。
3. **数据表设计有闭环意识**：8 张表通过外键关联（products -> contents ->
   scripts -> videos -> ads/leads -> reviews），不是孤立的 Excel。
4. **交付物齐全**：流程图、CSV 样例、SOP、视图说明、视频演示一应俱全。

## 四、缺点与风险（对照 67 分评估的扣分点）

| 评估扣分点 | 重构前的问题 | 本次是否解决 |
| --- | --- | --- |
| 数据闭环未打通 | 复盘程序读取 CSV，但结果只写 txt，不写回数据库；脚本助手也不回写 | 已解决 |
| 硬编码 / 表结构错误 | 部分模拟数据硬编码；平面表缺真实关联 | 已解决 |
| 工程规范差 | 密钥明文风险、无 README、无依赖说明、无完整测试 | 已解决 |
| 安全与异常处理弱 | requests 调用散落三处，异常处理不统一 | 已解决 |
| 知识库未落地 | prompts.json 只做展示，工作流/智能体没有真正加载 | 已解决 |
| 复盘算法有误 | 跳出率字段根本没进数据表，异常判断形同虚设 | 已解决 |

额外发现的问题：

- 三份脚本重复实现 `call_deepseek`，改一处要同步改三处；
- 配置、打印、文件写入、数据读写全部耦合在脚本里，无法做 Web 演示；
- 无日志，出问题只能看终端；
- 无前端，面试只能口头描述，不能现场操作；
- `drop2s`（2 秒跳出率）在代码里被读取，但 ads.csv 里根本没有这一列，
  导致“跳出率高”分支永远不会触发。

## 五、开源项目对标

### 1. MoneyPrinterTurbo（20k+ stars）

最核心的借鉴点：**同一条业务同时提供 WebUI、API、CLI 三种入口**，
控制器/服务/模型分层，首次启动自动生成配置文件，支持多种大模型 Provider。

### 2. TikTok Viral Factory（LangGraph 多智能体）

最核心的借鉴点：**每个 Agent 只做一件事，由 Supervisor 路由**；配置用类型化
Settings；22 个 Pydantic 数据模型集中管理；提示词按目录拆分；把 Agent
暴露为 MCP 工具。

### 3. ContentEngineAI（批量流水线）

最核心的借鉴点：**端到端流水线 + 平台化元数据 + 已发布商品注册表**，
每一步都有输入/输出文件，方便回溯与批量重跑。

### 4. Dify / Coze（工作流平台）

最核心的借鉴点：**工作流可观测（每步有记录）、知识库可沉淀、任务异步执行**。
用户不看代码也能理解 AI 在干什么。

## 七、面试演示建议

1. 现场演示用 `MOCK_AI=true`（或页面勾选“离线演示”），保证网络/额度不影响。
2. 开场先讲业务闭环：选品 -> 内容 -> 脚本 -> 视频 -> 投流 -> 复盘 -> 知识库。
3. 打开 WebUI 先展示“概览”，再依次跑一遍脚本助手、工作流、复盘，
   强调每一步都真实写回数据表，最后在 SQLite 里验证新增记录。
4. 被问“为什么这么设计”时，回答顺序：分层解耦 -> 统一 LLM 客户端 ->
   数据闭环 -> 任务队列 -> Mock 模式，每一点都能对到开源项目。
